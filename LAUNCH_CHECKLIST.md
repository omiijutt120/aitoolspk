## Build-tool advisory exception

The package registry currently reports one unpatched advisory, [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), affecting braces and its five-package Next.js lint dependency chain. The latest published braces is 3.0.3; the advisory lists no patched version. These packages are **dev-only** and process repository-owned lint globs, not public web requests; the deployed application is a static export. No new dependency is introduced to process untrusted remote patterns.

`launch:check` accepts only this exact advisory, only in the named dev-only chain, and still enforces a clean production audit. A new advisory, critical severity or a move into production dependencies fails the check. Keep reviewing for an upstream release. Do not run `npm audit fix --force`, which currently proposes incompatible framework/tool downgrades. ESLint 9 is retained because the current Next.js React/import/accessibility plugins do not declare ESLint 10 compatibility; this is also a toolchain maintenance limitation.

Patched findings: csv-parse upgraded to 7.0.3 ([advisory](https://github.com/advisories/GHSA-8cw4-87c7-c6xx)); sharp upgraded/overridden to 0.35.5 ([advisory](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)); compression overridden to 1.8.2 ([advisory](https://github.com/advisories/GHSA-vc2v-76pw-4v95)). Verify the actual installed tree and audits before later releases.

## Launch sequence and rollback

1. Confirm CI is green for the release commit. Complete the commercial checkpoints for plans you will represent as approved.
2. Configure the chosen host and domain using the README and [GitHub's domain instructions](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Preserve the currently correct GitHub DNS records; earlier loopback observations are resolved.
3. For GitHub Pages, the current build targets the **custom domain root**. It is not a build for `username.github.io/aitoolspk/`. Configure the domain before running **Publish custom-domain website**; the workflow is deliberately manual and requires the domain-ready input.
4. Confirm the host serves the export, deep links and assets over HTTPS. Check a parent, a plan, filters, WhatsApp, policy pages, sitemap, robots and 404s on the actual domain.
5. Inspect actual response headers, then complete Search Console and physical-device checks. Record the release commit and live URL here.
6. To roll back, deploy the last known good commit/artifact, keep the domain unchanged, and recheck the same live URLs. Never resolve a rollback by publishing `private/` or the raw supplier CSV.

**Public-domain launch is not complete until L05–L08 are verified.** An owner-private Sites preview and a public GitHub repository are separate from that domain launch.
